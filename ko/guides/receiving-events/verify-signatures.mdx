이 가이드에서는 SDK로 서명을 검증하는 방법을 설명합니다. 서명 방식 자체에 대한 설명은 [서명](/ko/concepts/signatures)을 참조하세요.

<Steps>
  <Step title="서명 비밀 키 찾기">
    대시보드에서 엔드포인트를 열고 **서명 비밀 키** 옆의 **Reveal**을 클릭합니다. 서명 비밀 키는 `whsec_`로 시작합니다.

    이 값을 `RELAYBOX_SIGNING_SECRET`이라는 환경 변수에 저장합니다.
  </Step>

  <Step title="원시 본문 읽기">
    요청 본문이 JSON으로 파싱되기 **전에** 접근할 수 있도록 프레임워크를 설정합니다. 설정 방법은 프레임워크마다 다르며, 아래 예제에서는 많이 사용되는 프레임워크를 중심으로 다룹니다.
  </Step>

  <Step title="검증 후 처리하기">
    <VerifySignature />
  </Step>

  <Step title="테스트하기">
    CLI로 올바르게 서명된 이벤트를 보낸 다음, 위조된 이벤트를 보내 제대로 거부되는지 확인합니다.

    ```bash
    # 수락되어야 합니다
    relaybox trigger order.paid

    # 400 응답과 함께 거부되어야 합니다
    curl -X POST http://localhost:3000/webhooks \
      -H "Relaybox-Signature: v1,not-a-real-signature" \
      -d '{"type": "order.paid"}'
    ```
  </Step>
</Steps>

## 문제 해결 {#troubleshooting}

<AccordionGroup>
  <Accordion title="모든 요청이 검증에 실패하는 경우">
    파싱한 뒤 다시 직렬화한 본문을 검증하고 있을 가능성이 매우 높습니다. `verify()`에 전달하는 바이트를 그대로 로그에 기록하고, 전송 로그에 표시된 페이로드와 비교하세요.
  </Accordion>

  <Accordion title="프로덕션 환경에서만 검증에 실패하는 경우">
    프로덕션 환경에서 프로덕션 엔드포인트의 시크릿을 사용하고 있는지 확인하세요. 엔드포인트마다 고유한 시크릿이 있으며, 테스트 엔드포인트와 프로덕션 엔드포인트가 시크릿을 공유하는 경우는 없습니다.
  </Accordion>

  <Accordion title="“timestamp too old” 오류로 검증에 실패하는 경우">
    서버 시계가 맞지 않습니다. NTP가 실행 중인지 확인하세요. 임시방편으로 SDK에서 허용 오차를 늘릴 수 있지만, 15분을 넘기지 않도록 설정하세요.
  </Accordion>
</AccordionGroup>
