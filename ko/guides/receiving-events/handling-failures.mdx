장애는 언제든 발생할 수 있습니다. Relaybox는 사용자 측 시스템이 몇 시간 동안 중단되더라도 이벤트가 단 하나도 유실되지 않도록 설계되었습니다.

## 짧은 장애가 발생한 경우 {#during-a-short-outage}

장애가 {maxRetryWindow} 미만이라면 따로 조치할 필요가 없습니다. Relaybox가 [자동으로 재시도](/ko/concepts/delivery/retries)하므로 엔드포인트가 복구되면 모든 이벤트가 전달됩니다.

<Tip>
  데이터베이스 마이그레이션처럼 장애가 미리 예정되어 있다면 먼저 [엔드포인트를 일시 중지](/ko/concepts/endpoints#endpoint-states)하세요. 이벤트는 대기열에 쌓였다가 엔드포인트를 재개하면 순서대로 전달되며, 재시도 횟수도 소모되지 않습니다.
</Tip>

## 장시간 장애 이후 {#after-a-long-outage}

엔드포인트가 재시도 기간보다 오래 중단되었다면 일부 이벤트는 **failed**로 표시됩니다. 엔드포인트를 복구한 후 이러한 이벤트를 재전송하세요.

<Tabs>
  <Tab title="대시보드">
    1. 엔드포인트를 열고 **Failed** 필터를 선택합니다.
    2. 장애가 발생한 시간 범위를 선택합니다.
    3. **Replay all**을 클릭합니다. Relaybox에서 전송될 이벤트 수를 표시하고 확인을 요청합니다.
  </Tab>

  <Tab title="CLI">
    ```bash
    relaybox events replay \
      --endpoint ep_5Np8Wz \
      --status failed \
      --since "2026-10-18T02:00:00Z" \
      --until "2026-10-18T09:30:00Z"
    ```
  </Tab>

  <Tab title="API">
    [이벤트 재전송](/ko/api-reference/events/replay)을 참조하세요.
  </Tab>
</Tabs>

## 알림 받기 {#get-alerted}

장애 소식을 고객에게서 먼저 듣는 일이 없도록 하세요. **Settings → Alerts**에서 알림을 받을 조건을 선택할 수 있습니다.

| 알림                    | 발생 조건                                        |
| --------------------- | -------------------------------------------- |
| **Failure rate**      | 5분 동안 실패한 시도의 비율이 지정한 값을 넘을 때                |
| **Backlog**           | 엔드포인트에서 가장 오래 대기 중인 이벤트의 대기 시간이 지정한 기간을 넘을 때 |
| **Endpoint disabled** | 5일간 실패가 계속되어 Relaybox가 엔드포인트를 비활성화했을 때       |

알림은 이메일, Slack, PagerDuty는 물론 Relaybox 엔드포인트를 포함한 모든 웹훅 URL로 보낼 수 있습니다.

<Warning>
  모니터링 대상과 같은 인프라에 의존하는 엔드포인트로*만* 알림을 보내지 마세요. 그 인프라가 다운되면 알림도 받을 수 없습니다.
</Warning>
