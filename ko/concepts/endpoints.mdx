**엔드포인트**는 이벤트를 수신하는 URL입니다. 이벤트를 게시하면 Relaybox는 해당 이벤트 유형을 구독 중인 활성화된 엔드포인트 모두에 이벤트를 전달합니다.

## 엔드포인트 만들기 {#create-an-endpoint}

엔드포인트는 대시보드에서 만들거나 [API](/ko/api-reference/endpoints/create)로 만들 수 있습니다.

<Tabs>
  <Tab title="대시보드">
    1. **Endpoints**로 이동한 후 **Add endpoint**를 클릭합니다.
    2. URL을 입력합니다. 프로덕션 환경에서는 반드시 HTTPS를 사용해야 합니다.
    3. 구독할 이벤트 유형을 선택하거나 **All events**를 선택합니다.
    4. **Create**를 클릭합니다. 서명 비밀 키는 한 번만 표시되므로 지금 바로 복사해 두세요.
  </Tab>

  <Tab title="API">
    ```bash
    curl https://api.relaybox.dev/v3/endpoints \
      -H "Authorization: Bearer $RELAYBOX_API_KEY" \
      -d url="https://example.com/webhooks" \
      -d "event_types[]=order.*" \
      -d description="Order notifications for the fulfillment team"
    ```
  </Tab>

  <Tab title="CLI">
    ```bash
    relaybox endpoints create https://example.com/webhooks --events "order.*"
    ```
  </Tab>
</Tabs>

## 엔드포인트 상태 {#endpoint-states}

모든 엔드포인트는 다음 네 가지 상태 중 하나입니다.

<AccordionGroup>
  <Accordion title="활성화됨" icon="circle-check">
    엔드포인트가 이벤트를 정상적으로 수신합니다. 새 엔드포인트는 기본적으로 이 상태입니다.
  </Accordion>

  <Accordion title="일시 중지됨" icon="circle-pause">
    사용자가 엔드포인트를 수동으로 일시 중지한 상태입니다. Relaybox는 이벤트를 최대 72시간 동안 대기열에 보관하며, 엔드포인트를 재개하면 순서대로 전달합니다.
  </Accordion>

  <Accordion title="비활성화됨" icon="circle-xmark">
    엔드포인트가 5일 연속으로 모든 전달 시도에 실패하여 Relaybox가 전달을 중단한 상태입니다. 비활성화되기 전에 계정 소유자에게 이메일로 알려 드립니다. 비활성화 기간 동안 게시된 이벤트는 대기열에 보관되지 **않지만**, 나중에 재전송할 수 있습니다.
  </Accordion>

  <Accordion title="확인 대기 중" icon="hourglass-half">
    Enterprise 플랜에서 **Require endpoint verification**이 켜져 있으면, 새 엔드포인트는 이벤트를 수신하기 전에 확인 요청(challenge request)에 응답해야 합니다.
  </Accordion>
</AccordionGroup>

## 전달 속도 제한 {#rate-limiting-delivery}

기본적으로 Relaybox는 엔드포인트가 응답할 수 있는 최대 속도로 이벤트를 전달합니다. 서버가 이 속도를 감당하지 못한다면 다음과 같이 속도 제한을 설정하세요:

```json
{
  "rate_limit": {
    "requests": 50,
    "per": "second"
  }
}
```

한도를 초과한 이벤트는 실패 처리되지 않고 대기열에서 대기합니다. 대기열의 이벤트는 게시된 순서대로 처리됩니다.

<Warning>
  속도 제한이 게시 속도보다 낮으면 대기열이 끝없이 늘어납니다. 엔드포인트의 백로그가 1시간 넘게 밀리면 Relaybox에서 알림을 보냅니다.
</Warning>
