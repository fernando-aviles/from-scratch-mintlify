APIキーは、Relaybox APIへのリクエストの認証に使用します。各キーは1つの環境に属し、作成時に一度だけ表示されます。

<ApiKeyWarning />

## キーのプレフィックス {#key-prefixes}

キーの用途はプレフィックスで判別できます。

| プレフィックス     | 環境    | 用途                                                                                                  |
| ----------- | ----- | --------------------------------------------------------------------------------------------------- |
| `rbx_test_` | テスト   | ローカル開発や CI。イベントは配信されますが、課金は発生しません。                                                                  |
| `rbx_live_` | 本番    | 本番環境のサービス。                                                                                          |
| `rbx_pub_`  | いずれも可 | フロントエンドへの[カスタマーポータル](/ja/guides/sending-events/fan-out#customer-portal)の埋め込み。公開可能キーではイベントを発行できません。 |

## スコープ {#scopes}

デフォルトでは、新しいキーはその環境へのフルアクセス権を持ちます。セキュリティを高めるため、各サービスには必要なスコープのみを付与してください。

<ParamField path="events:write" type="scope">
  イベントを発行します。通常、プロデューサーサービスに必要なスコープはこれだけです。
</ParamField>

<ParamField path="events:read" type="scope">
  イベントと配信試行の一覧表示および取得を行います。
</ParamField>

<ParamField path="endpoints:write" type="scope">
  エンドポイントの作成、更新、削除、およびシークレットのローテーションを行います。
</ParamField>

<ParamField path="endpoints:read" type="scope">
  エンドポイントの一覧表示および取得を行います。署名シークレットへのアクセスは含まれません。
</ParamField>

## キーをローテーションする {#rotate-a-key}

キーをローテーションすると、同じスコープを持つ新しいキーが作成され、古いキーは削除がスケジュールされます。

1. **Settings → APIキー** に移動し、対象のキーを探します。
2. **Rotate** をクリックし、古いキーを引き続き使用できる期間を「即時」「1時間」「24時間」「7日間」から選択します。
3. 新しいキーをコピーし、古いキーの有効期限が切れる前にサービスへデプロイします。

<Note>
  キーが漏洩した可能性がある場合は、**Immediately** を選択してください。古いキーを使用したリクエストは、ただちに `401 unauthenticated` で失敗するようになります。
</Note>
